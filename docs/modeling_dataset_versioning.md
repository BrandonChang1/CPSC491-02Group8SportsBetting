# Modeling Dataset Versioning

## Purpose

The modeling dataset versioning process provides a reproducible
method for generating model-training data from stored historical
NBA records.

The process allows changes to the underlying historical data or
dataset-generation logic to be identified.

## Dataset Generation

The modeling dataset is generated by:

`data/processing/modeling_dataset.py`

Historical data is read from the PostgreSQL `games` and
`player_game_stats` tables.

Dataset generation is read-only and does not update, delete, or
otherwise modify the original historical database records.

## Dataset Version

The dataset-generation process uses a semantic version identifier.

Current version:

`1.0.0`

The version represents the structure and generation rules used to
produce the modeling dataset.

The version should be updated when the modeling dataset schema or
generation process changes.

Examples:

- Patch: `1.0.0` to `1.0.1`
  - Minor generation fixes that do not intentionally change the
    dataset structure.

- Minor: `1.0.0` to `1.1.0`
  - New modeling fields or backward-compatible feature additions.

- Major: `1.0.0` to `2.0.0`
  - Significant or incompatible dataset-structure changes.

## Generation Identifier

Each generated dataset receives a SHA-256 hash calculated from the
CSV contents.

The first 12 characters of the SHA-256 hash are included in the
filename.

Example:

`nba_modeling_dataset_v1.0.0_a53d71f21c82.csv`

The same source data and generation process should produce the same
dataset contents and therefore the same SHA-256 hash.

Changes to the historical data or generated dataset will produce a
different hash.

## Metadata

Each dataset is accompanied by a metadata JSON file containing:

- Dataset version
- Generation identifier
- UTC generation timestamp
- Row count
- Modeling columns
- Deterministic sort order
- Full SHA-256 hash
- Source description
- Generation method

Example:

`nba_modeling_dataset_v1.0.0_a53d71f21c82.metadata.json`

The timestamp is stored in metadata rather than inside the modeling
dataset so it does not affect dataset reproducibility.

## Required Modeling Fields

Version 1.0.0 includes:

- player_id
- game_id
- game_date
- minutes
- points
- rebounds
- assists
- plus_minus
- opponent_team_id
- is_home
- recent_minutes_avg

## Deterministic Ordering

Rows are sorted by:

1. player_id
2. game_date
3. game_id

This ensures that identical source data is generated in the same
order.

## Generated Files

Generated datasets are stored under:

`data/modeling/`

These artifacts are excluded from Git because they can be recreated
from the stored historical data and generation code.

The generation code, tests, and versioning documentation are tracked
in Git.

## Running Dataset Generation

From the project root:

`python -m data.processing.modeling_dataset`

The command prints the dataset version, row count, SHA-256 hash,
dataset path, and metadata path.
